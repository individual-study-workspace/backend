# 강의실 생성 기능 (Create Classroom)

> BMad 계획 문서 · 작성일 2026-07-12
> 브레인스토밍에서 확정한 범위·설계를 팀/세션 간 정렬용으로 고정한다.

---

## 1. 한 줄 요약

인증된 사용자가 **강의실(classroom) 1개 + 청구정책(billing_policy) 1개를 한 트랜잭션으로 생성**하는 API를 만든다. 생성자는 강의실의 owner(선생님)이며, 초대코드가 자동 발급된다.

## 2. 범위 (Story Scope)

| 포함 | 제외 (다음 스토리) |
|------|-------------------|
| `classroom` 테이블·엔티티·마이그레이션 | `class_member` (멤버 등록/초대 참여) |
| `billing_policy` 테이블·엔티티 (1:1) | 강의실 조회/수정/삭제 API |
| `POST /api/v1/classrooms` 생성 API | 회차/스케줄 자동 생성 (`total_sessions` 기반) |
| 초대코드 자동 발급 | 청구 실행/결제 로직 |

- 결정: 생성 시 강의실과 청구정책을 **함께** 저장한다. 생성자를 멤버로 자동 등록하지 **않는다**.

## 3. 확정된 설계 결정 (브레인스토밍 결과)

1. 고정 코드값(class_type/repeat_type/payment_type)은 **Java enum**(`@Enumerated(STRING)`) — 기존 Role/AuthProvider 방식. code_management 미사용.
2. `class_days`는 **다중 요일 CSV** (`"MON,WED,FRI"`) 를 `VARCHAR`에 저장.
3. 청구 모델:
   - `MONTHLY`(월별): 매월 `billing_day`일에 `amount`원 청구, `billing_unit` = null
   - `PER_SESSION`(회차별): `billing_unit`회마다 `amount`원 청구, `billing_day` = null
4. `billing_policy` ↔ `classroom` = **1:1** (`class_id` UNIQUE FK).
5. 컨벤션 자동 교정: `INT(11)`→`BIGINT`, `TIMESTEMP`→`DATETIME(6)`, `invite_cde`→`invite_code`, `amount`는 정수(원).

## 6. API 스펙

### `POST /api/v1/classrooms`  (인증 필요)

Request body:
```json
{
  "name": "고3 수학 심화반",
  "classType": "ONLINE",
  "repeatType": "WEEKLY",
  "classDays": ["MON", "WED", "FRI"],
  "fromDate": "2026-08-01",
  "fromTime": "19:00",
  "totalSessions": 24,
  "remark": "교재 별도",
  "billingPolicy": {
    "paymentType": "MONTHLY",
    "billingDay": 5,
    "billingUnit": null,
    "amount": 300000
  }
}
```

Response `201 Created` (ApiResponse 래핑):
```json
{
  "success": true,
  "data": {
    "id": 1,
    "name": "고3 수학 심화반",
    "classType": "ONLINE",
    "repeatType": "WEEKLY",
    "classDays": ["MON","WED","FRI"],
    "fromDate": "2026-08-01",
    "fromTime": "19:00",
    "totalSessions": 24,
    "inviteCode": "K7Q2XM9A",
    "remark": "교재 별도",
    "createdBy": 42,
    "createdAt": "2026-07-12T10:00:00Z",
    "billingPolicy": {
      "paymentType": "MONTHLY",
      "billingDay": 5,
      "billingUnit": null,
      "amount": 300000
    }
  },
  "error": null
}
```

### 검증 규칙 (Bean Validation + 서비스 교차검증)
- `name`: 필수, 1~20자
- `classType`: 필수(enum). null이면 ONLINE 기본.
- `remark`: 최대 500자
- `billingPolicy.amount`: 필수, > 0
- 교차검증:
  - `MONTHLY` → `billingDay` 필수(1~28), `billingUnit`은 무시(null 저장)
  - `PER_SESSION` → `billingUnit` 필수(≥1), `billingDay`는 무시(null 저장)
- `classDays` 원소는 `MON~SUN`만 허용 → 엔티티엔 CSV로 저장

### 인증/권한
- `@AuthenticationPrincipal CustomUserPrincipal principal` → `principal.userId()` 를 `created_by`로.
- 인증된 사용자면 누구나 생성 가능(생성자가 owner).

## 7. 핵심 로직

- **초대코드 발급**: 안전 alphabet 8자 랜덤 → `existsByInviteCode`로 중복 확인, 충돌 시 재시도(최대 N회). 최종 실패 시 `INVITE_CODE_GENERATION_FAILED`.
- **트랜잭션**: `@Transactional` 안에서 Classroom 저장 → BillingPolicy 저장(생성된 class_id 참조). 한쪽 실패 시 전체 롤백.
- **enum 매핑**: `@Enumerated(EnumType.STRING)`.
- **class_days 변환**: DTO `List<DayOfWeek>`(또는 String) ↔ 엔티티 CSV String. 응답 시 다시 List로.

## 8. 에러코드 추가 (ErrorCode enum)
```
CLASSROOM_INVALID_BILLING_POLICY (400) - 청구정책 입력이 유효하지 않습니다
INVITE_CODE_GENERATION_FAILED    (500) - 초대코드 생성에 실패했습니다
```
(그 외 검증 실패는 기존 VALIDATION_FAILED / GlobalExceptionHandler 처리)
